## As 14 decisões

1. Modelo híbrido de conteúdo: ingere tudo, persiste só metadata derivada + scores; UI = resumo próprio + hotlink fotos + deep link. (ADR-001)
2. `Property` agrega N `Listing` — dedup não destrutivo. (ADR-001)
3. MTR tri-estado: DECLARED / INFERRED(confiança) / UNKNOWN. (ADR-001)
4. Fotos: hotlink + fallback placeholder + "Ver N fotos na fonte →". Zero cópia. (ADR-002)
5. Raw data: só payloads de erro, TTL 30d; `normalizer_version` por Listing. (ADR-002)
6. Matching conservador (geo ponderado por fonte) + GrayQueue; falso negativo > falso positivo. (ADR-002)
7. Fairness score: ComparisonPopulation hierárquica por MtrClass (bairro n≥8 → cidade n≥15 → LTR × MtrPremium). (ADR-003)
8. MonthlyEquivalentPrice por Listing; score por listing, range na Property. (ADR-003)
9. Cold start honesto: "dados insuficientes" + contexto, nunca score fabricado. (ADR-003)
10. Alertas: 3 eventos (PropertyCreated, ListingCreated em property conhecida, PriceChanged). (ADR-004)
11. Thresholds: absoluto (Free) / relativo à mediana móvel (Pro). (ADR-004)
12. Property lifecycle ACTIVE→DELISTED→REACTIVATED; graveyard = ativo de dados; contactos de anunciante purgados ao delistar. (ADR-004)
13. Receita: subscrição €9,90 + SearchPass €14,90/30d; EntitlementGrant{origin, expires_at}; MarketReport grátis antecipado para Fase 2. (ADR-005)
14. Módulo `agent`→`intelligence`; score em read-model + FairnessScorePort; sem ciclo listing↔intelligence. (ADR-006)

## Decisões de sessão anteriores mantidas

- Stack: Kotlin + Spring Boot 3 + Spring Modulith + Langchain4J + Angular 19 (SSR obrigatório).
- Vector DB: REVISITAR — pgvector na Fase 1 recomendado; Milvus quando >1M embeddings (sizing CX22 4GB inviável para Milvus Standalone + Postgres + Redis + JVM).
- Fontes: Idealista, Imovirtual, OLX (Fase 1), Airbnb + FB (Fase 2).
- Pricing mediana + IQR (mantido, agora com população segmentada por MtrClass).
