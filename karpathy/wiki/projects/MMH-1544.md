# MMH-1544: Company & Seller Filter Missing in BFF Endpoints
- **Project**: MMH
- **Ticket ID**: MMH-1544
- **Processing Date**: 2026-06-12
- **Status**: Implemented
- **Tags**: #ticket #implementation #access-control #bff #dry

## Summary
The `x-brokers` header (company filter) and `x-seller-id` header (seller filter) were already applied in the main list endpoints but missing in 3 BFF endpoints. This meant users could see deals from all companies and all sellers regardless of their access scope. Extracted shared logic into `buildAccessFilter()` utility to follow DRY principles.

## Implementation Details

### New Utility: `server/utils/accessControl.ts`
Created `buildAccessFilter(event)` — a shared utility that parses two headers into a MongoDB filter object:

| Header | MongoDB field | Behavior |
|--------|---------------|----------|
| `x-brokers` | `dealership_id: { $in: [brokerIds] }` | Company-level filter |
| `x-seller-id` | `seller_id: { $in: [brokerIds] }` | Seller-level filter (only for pure SELLER role) |

Follows existing naming conventions (`buildPagination`, `buildSort`, `buildDateFilter`, `buildFacets`).

### Refactored Endpoints (now use shared utility)
- **`server/api/deals.get.ts`** — replaced inline header parsing with `buildAccessFilter(event)`
- **`server/api/deal-list.get.tsx`** — replaced inline header parsing with `buildAccessFilter(event)`

### Fixed Endpoints (were missing both filters)
- **`server/api/deals/[id].get.ts`** — added `...accessFilter` to both `findOne` queries
- **`server/api/dashboard/stats.get.ts`** — added `...accessFilter` to 3 `countDocuments` calls, renamed `_event` → `event`
- **`server/api/deals/pick-list.post.ts`** — added `Object.assign(f, accessFilter)` to scope distinct queries

## Key Design Decisions
- **DRY approach**: extracted shared logic to avoid 5x duplication of the same header parsing
- **Pattern consistency**: follows existing conventions (`buildPagination`, `buildSort`, `buildDateFilter`, `buildFacets`)
- **Company filter**: `x-brokers` → `dealership_id: { $in: [brokerIds] }`
- **Seller filter**: `x-seller-id` → `seller_id: { $in: [brokerIds] }` (only sent for pure SELLER role)
