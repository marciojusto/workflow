## Summary
Implemented full RBAC for the **SELLER** role across hyperfront. A pure seller can only see their own deals (filtered by `brokerContactId`), cannot reattribute deals to other salespeople, and commission visibility is gated. Managers (SALES_MANAGER) retain full visibility. All changes align with the Excel RBAC matrix.

## Implementation Details

### AC01 — Deal Filtering by Owner (`x-seller-id` Header)

**Backend MongoDB `$match`:**
- Pure SELLER sends their `brokerContactId` as `x-seller-id` header
- Backend stages a `$match: { seller_id: <x-seller-id> }` filter
- Combined roles `SELLER+SALES_MANAGER` bypass the filter and see all deals

**Frontend header injection:**
- `shared/utils/api.ts` — injects `x-seller-id` header when user has SELLER role
- `getAccessToken()` 3-tier fallback: Okta SDK → `authStore` → `okta-token-storage` → legacy
- `getIdToken()` reads `okta-token-storage` for `x-id-token` header

### AC03 — Navigation Menu & Offer Access

- Added `Roles.SELLER` to `offer/edit.vue` `allowedRoles`
- SELLER can access `POST /api/deals/proposals` per Excel RBAC matrix

### AC04 — Cannot Reattribute Deals

- `SmartServerTable.vue` — new `hiddenActions` prop (defaults to `[]`)
- `deal/list.vue` passes `hiddenActions: ['reattribute']` for SELLER role
- `canReattribute` gate restricted to `SALES_MANAGER + ADMIN` only

### AC06 — Commission Visibility

- `OfferDetails.vue` — new `canSeeCommissions` computed gate
- Commission section hidden for SELLER without `SELLER_COMMISSION_VISIBILITY` or `DEALER_COMMISSION_VISIBILITY` roles

### Cross-Cutting Auth Infrastructure

- **Middleware** `00-authGuardHandler.ts`:
  - `matchRoute()` with parameterized path matching (`:id` wildcard)
  - `BFF_ROUTE_ROLES` map: added `GET/PUT /api/deals/:id`, `GET /api/deals/:id/documents`
- **Role resolution chain** `oktaUserinfo.ts`:
  - `/userinfo` → `idToken` claims → `accessToken` claims
- **Auth store** `notifyOnError: false` fixes to prevent infinite loops

## Key Decisions
- **`x-seller-id` header approach** — backend-driven filtering, avoids over-fetching
- **Manager bypass** — `SELLER+SALES_MANAGER` combined roles see all deals (no filter)
- **`hiddenActions` prop** — generic mechanism usable by future roles/ACs
- **3-tier token fallback** — resilience against Okta SDK timing issues
