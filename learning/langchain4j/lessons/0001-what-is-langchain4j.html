The big picture

LangChain4J is the JVM port of the LangChain framework. It gives you abstractions for the common patterns you hit when wiring LLMs into applications: chaining calls, remembering conversation history, retrieving documents, calling external tools, and coordinating multiple agents.

If you have seen Python LangChain, the concepts translate directly. The difference is idiomatic Java: type-safe interfaces, Spring Boot integration, and first-class support for Java 21 features like virtual threads and structured concurrency.

Core abstractions

At the bottom of every LangChain4J app are three things:

  1. ChatModel — the LLM itself. Think of it as a Supplier<String> that takes a prompt and returns a completion.
  2. AiServices — a typed interface that LangChain4J implements for you. You declare methods like String chat(String message) and the framework builds the implementation at runtime.
  3. ChatMemory — where conversation history lives. Without it, every call is stateless.
// 1. Define your AI service as a plain Java interface
public interface Assistant {
    String chat(String message);
}

// 2. Create a ChatModel (backed by Kilo.ai)
OpenAiChatModel model = OpenAiChatModel.builder()
    .apiKey("your-kilokey")
    .baseUrl("https://api.kilo.ai/v1")   // Kilo.ai endpoint
    .modelName("kilomodel")              // check Kilo.ai docs for model ID
    .build();

// 3. Build the service
Assistant assistant = AiServices.create(Assistant.class, model);

// 4. Use it
String reply = assistant.chat("Explain RAG in one sentence.");
System.out.println(reply);

That is the entire lifecycle. No builders beyond the model, no manual HTTP, no JSON parsing. LangChain4J handles streaming, retries, and token counting if you ask it to.

How it compares to plain HTTP

Without LangChain4J you would write an HTTP client, build a JSON request, parse the response, and manage conversation history yourself. LangChain4J replaces all of that with typed interfaces and pluggable components.

Key insight
LangChain4J is not an agent framework first. It is an abstraction layer for LLM interactions. Agents, RAG, and tool calling are built on top of AiServices and ChatModel.

Setting up your project

Add LangChain4J and the OpenAI-compatible module to your build file. Kilo.ai exposes an OpenAI-compatible API, so the langchain4j-open-ai module works out of the box.

Maven

<dependency>
    <groupId>dev.langchain4j</groupId>
    <artifactId>langchain4j</artifactId>
    <version>1.0.0</version>
</dependency>
<dependency>
    <groupId>dev.langchain4j</groupId>
    <artifactId>langchain4j-open-ai</artifactId>
    <version>1.0.0</version>
</dependency>

Gradle (Kotlin DSL)

implementation("dev.langchain4j:langchain4j:1.0.0")
implementation("dev.langchain4j:langchain4j-open-ai:1.0.0")

Check the Maven Central page for the latest version. Replace 1.0.0 with the current stable release.

Try it yourself

Create a simple Maven project, add the dependencies above, and paste the code sample. Run it against your Kilo.ai key. If you get a response, you have your first working LangChain4J integration.

Stuck?
If Kilo.ai uses a non-standard endpoint or auth scheme, check the Kilo.ai docs and adapt the baseUrl and headers accordingly. The OpenAiChatModel builder accepts a custom httpClientBuilder for exotic setups.
